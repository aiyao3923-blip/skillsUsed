# 工具边界与独立核验

## 1. 执行宿主与版本边界

使用核验过的PowerShell 7+和桌面Microsoft Word，脚本不支持Windows PowerShell 5.1；不添加Bypass、不更改系统安全设置。扫描不启动Word；生成与Word校验使用本任务独立实例。文档/网络类Python按本机环境说明选择绝对解释器；没有必需模块时如实说明，未经授权不安装。

2026-09-09修订将原有“裁去行尾/尾部空白、读取失败跳过、相同内容跨路径自动删除”改为保真收集与显式清单。旧文件的自洽校验记录不能代替新版本的独立检查；原Word版式构造保留。每次重要脚本变更仍需实际生成回归，不凭本段文字宣布通过。

## 2. 最小可复现调用

下面代码**在PowerShell 7会话中**运行；使用&调用脚本以正确传递数组，不把逗号拼成单个路径。替换项目事实与路径，工作/输出目录应在待扫描源码目录之外，且无同名旧输出。

~~~powershell
$skill = 'C:\Users\Administrator\.codex\skills\generate-ruanzhu-source-code'
$work = 'C:\path\to\review-work' # 本任务自己的已创建工作目录
$params = @{
    ProjectPath = 'C:\path\to\project'
    SystemName = '实际系统全称'
    Version = 'V1.0'             # 与实际登记版本核对
    OutputDirectory = 'C:\path\to\new-output'
}
$scan = & "$skill\scripts\generate-source-code.ps1" @params -ScanOnly
$scan | ConvertTo-Json -Depth 12 | Set-Content -LiteralPath "$work\source-before.json" -Encoding utf8
~~~

先对照实际项目核定清单，再确定排序。默认顺序合适就不另造参数。若有业务链依据，读取$scan.SourceFileDetails中的全部相对路径，整理为完整数组后设置$params.SourceOrder；改变参数后重新ScanOnly。必须精确覆盖候选，不补虚构路径，不悄悄漏掉测试/配置。明确限定范围才改用SourceFiles，不与SourceOrder混用。

如需本地注释/重复检查（不是每个小项目强制跑）：

~~~powershell
$python = 'C:\path\to\verified-environment\python.exe'
& $python -X utf8 "$skill\scripts\review-source.py" --manifest "$work\source-before.json" --output "$work\quality-review.json"
# 仅在用户已提供另一个项目清单且确需比较时追加 --compare-manifest '另一个清单.json'
~~~

人工完成系统特色、注释语义、重复分类、范围和内容安全审查；获准的源码修改完成并验证后，重新扫描冻结版本。再以相同参数生成并保存返回对象：

~~~powershell
$generated = & "$skill\scripts\generate-source-code.ps1" @params
$generated | ConvertTo-Json -Depth 12 | Set-Content -LiteralPath "$work\source-generated.json" -Encoding utf8
& "$skill\scripts\validate-output.ps1" -OutputDirectory $params.OutputDirectory -SystemName $params.SystemName -Version $params.Version
& $python -X utf8 "$skill\scripts\verify-source-export.py" --manifest "$work\source-generated.json" --docx "$($params.OutputDirectory)\源程序代码.docx" --pdf "$($params.OutputDirectory)\源程序代码.pdf" --system-name $params.SystemName --version $params.Version --output "$work\export-check.json"
~~~

如果关闭页脚：生成参数添加NoFooterPageNumber=$true，Word校验追加-NoFooterPageNumber，Python核验追加--no-footer。上例Python路径是待核验替换项，不允许把它当已存在环境。JSON报告默认拒绝覆盖已有文件；复验用新文件名，不覆盖源码或用户报告。

## 3. 清单的证据含义

- ScanOnly与生成返回同一类清单对象；扫描结果没有真实页数，不冒称已生成。返回对象由调用者显式保存，工具不把源码正文或秘密复制到清单。
- ProjectPath、SelectionStrategy/SelectionMode、SourceFiles、SourceFileDetails说明实际收集范围和顺序；自动范围仍须人审。指定范围不冒称全系统。
- RawSha256是每文件原始字节指纹；Sha256是编码/换行规范化文本指纹；DocumentSha256是tab打印展开后的逻辑文本指纹；SourceFingerprint是实际正文逻辑文本序列指纹。原始文件终止换行与打印行映射分别记录，不能因文件带一个终止LF就多印一行。
- LogicalLines含原有空白逻辑行、不含排版补白；空文件0行，StartLine=EndLine+1。StartLine/EndLine为汇编正文逻辑行，不等同于每页物理编号。
- DuplicateOf只是不同路径同内容的提示，默认不删文件。阅读失败、路径越界/链接风险、无效编码/不支持控制字符须处理后再生成。
- 默认Auto按严格UTF-8→GB18030→GBK尝试；有已知编码时用-SourceEncoding明确指定并核对文本，不把“能解码”当编码来源已确认。BOM作为编码标记处理，真实空白/字符串内容不得裁掉。
- 对比source-before与source-generated的范围、顺序和原始指纹，并再次读原文件；不一致说明冻结失效，要重新审查/生成。一个文档与自身元数据相等仅是自洽，不是独立来源证明，更不是权属或创新证明。

## 4. 三层机械核验与人工收口

1. **Word实测**：validate-output.ps1检查纸张/页边距、正文、动态页眉页脚、原生行号、物理行统计及元数据。无Acrobat时只能给出有限PDF证据，不能算完整通过。
2. **原文件→DOCX**：verify-source-export.py重新读取清单指定的原文件，校验原始哈希和逻辑行映射，再与DOCX正文逐行比较；真实空白尾行和排版补白分开。正文必须单段落、无额外封面/表格，元数据与独立重建值一致。
3. **最终PDF**：同工具用PyMuPDF检查每页A4、左栏可见编号恰为1—50、系统名/版本/PAGE/NUMPAGES、页脚，以及忽略排版空白后的可见源码字符；对照DOCX页数。Word实时页数还要与其结果一致，不只信缓存Pages域。
4. **人工**：实际看首、中、末页、长行/中文/特殊字符/超长系统名等风险页，检查重叠、截断、字体回退与首页起始内容。工具未证明字体/视觉全优，缺少文字层/复杂字形导致提取失败时先定位原因，换可靠方法复核，不能关掉检查后报通过。

Word校验的DocumentChecksPassed=True、ValidationStatus=Partial表示其内部检查通过；由于未对照原文件/PDF内容，Passed仍为False，即使退出0也不是整体通过。须结合独立核验与人工收口。Python导出核验的passed只描述其列明范围。审查工具不证明注释内容正确；导出核验不证明项目范围全部、独创性、法律受理或实际运行；自动工具未执行的视觉检查保持未验证。没有源码原件时不能补造原始指纹；没有PDF可见证据时不能把文件存在当逐页通过。
