# 软著工作流 Skills

整理与维护四个软件著作权相关技能，覆盖项目规划、操作手册、源程序材料与登记信息填报。每个技能以独立目录保存，保留 `SKILL.md`、界面元数据及配套参考资料、脚本和测试文件。

## 技能目录

| 技能 | 目录 | 主要用途 |
| --- | --- | --- |
| 软著思路 | [soft-copyright-ideas](./soft-copyright-ideas/SKILL.md) | 分析题目与业务场景、澄清需求，形成可追溯的系统及 UI 实施方案。 |
| 软著操作手册 | [generate-ruanzhu-manual](./generate-ruanzhu-manual/SKILL.md) | 根据真实项目资料、操作和截图编写并核验中文操作手册，支持 Word/PDF 交付。 |
| 软著源程序材料 | [generate-ruanzhu-source-code](./generate-ruanzhu-source-code/SKILL.md) | 审查真实项目源码，按规定版式生成与核验源程序代码 Word/PDF。 |
| 软著登记信息 | [complete-ruanzhu-registration-info](./complete-ruanzhu-registration-info/SKILL.md) | 根据源码、说明书与已确认法律事实填写登记信息，检查字段、字符限制与源码数量。 |

## 使用方式

1. 克隆本仓库，或下载所需技能的完整目录：

   ```bash
   git clone https://github.com/aiyao3923-blip/skillsUsed.git
   ```

2. 按所用工具的技能安装说明导入对应目录。不要只复制 `SKILL.md`；同目录下的 `agents/`、`references/`、`scripts/`、`evals/`（如有）应一并保留。
3. 阅读该技能的 `SKILL.md`，核对输入要求、执行边界及环境依赖后再使用。脚本所需的 Python 包、PowerShell、办公软件或其他工具，以各技能正文和脚本说明为准；本仓库不自动安装这些依赖。
4. 更换电脑或环境时，先核对技能中涉及的本机路径、解释器、外部工具和辅助技能是否可用，不直接照搬旧机器的配置。

私有仓库的克隆和下载需要相应 GitHub 访问权限；不要将密码或访问令牌写进命令示例、源码或提交记录。

## 推荐工作顺序

```text
软著思路 → 项目实际实现与验证 → 操作手册 / 源程序材料 → 登记信息
```

四个技能各有职责，不能互相替代：项目规划不等于已完成系统，操作手册不等于源程序材料，登记信息中的法律事实仍需由申请人确认。

## 内容与发布边界

- 生成材料应以真实项目、真实操作和已确认事实为依据，不虚构截图、源码或验证结果。
- 本次整理仅在源程序排版规范中匿名化了一组历史样本文件名，其余技能文件保持原始内容；排除 Python 缓存，并新增本仓库说明与 `.gitignore`。
- 不收录 Python 缓存、虚拟环境、环境变量文件、账号凭据或本次上传的本地检查记录。
- `.gitignore` 用于减少误提交，不能替代每次提交前的人工检查。
- 当前未额外添加开源许可证；公开可见与授予开源许可不是同一事项。

思路技能中的 `MIGRATION.md` 保留为历史迁移记录；其中提及的上级原始工作流和开发校验工具 `quick_validate.py` 未随本仓库提供，不是当前技能入口的核心运行依赖。

具体使用规范、质量检查及限制，以每个技能中的说明为准。
