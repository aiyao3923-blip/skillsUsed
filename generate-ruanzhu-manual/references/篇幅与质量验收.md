# 篇幅与质量验收

用于正式完整版的策划、扩写和交付验收。页数是深度预警指标，不是真实性、完整性或登记通过的充分条件。

## 1. 先写清约定和计数口径

回应主人现有手册说明不足的需求，本 skill 的正式完整版默认目标是：**最终 PDF 有效正文不少于70页**。这是本地详细版偏好，用户明确要求其他篇幅时按新约定执行；不适用于一次局部修改，不是对所有软件或所有用户的普遍标准。

计数须同时记录：PDF 总页数、正文首个物理页、正文末个物理页、排除页、有效正文页数。物理页从文件第一张开始计1，不能拿页眉打印的“1”当文件第1页。

- 封面、目录不计入正文。空白、仅分隔标题、重复占位及为了增页而拼接的材料不计有效页。
- 服务当前用户任务的实质参考附录可以计入；源码清单、无关原理综述、通用行业背景和大量重复截图不能拿来补数。
- 若正文一直延续到末页，原始正文页数为“PDF总页数－正文起始物理页＋1”；有效页数还须扣除不合格页。正文边界与排除页必须实际检查，不能仅从 DOCX 元数据、文件大小或字数推算。
- 在最终格式、目录更新和 PDF 导出后实测。修改截图大小、标题分页或目录后须重计；不能用试排估算宣布70页已经达标。

**两道门独立验收：内容真实且足够说明；有效篇幅满足约定。** 70页但核心流程讲不清，未通过；内容合格但低于约定，仍不能擅自称满足70页要求。

## 2. 从任务证据推算篇幅，不按页分配空话

在任务覆盖表中为复杂任务、普通任务和简短参考标注相对深度，列出需要的状态图、参数表、结果解释及异常分支。依据真实材料估算各部分区间，再用代表性任务试排校准。页预算跟随已确认任务调整，不给每章固定配额，也不把70当上限。

若预计或实测不足，依次审查真正缺少的信息：

1. 是否漏掉实际可见能力、输入模式、必经操作或跨模块衔接？
2. 核心任务是否只写了顺利路径，遗漏已存在的失败反馈和恢复后的验证？
3. 参数是否只有名字，没有单位、来源明确的默认值/范围、选择条件或结果影响？
4. 是否缺少完整案例的关键中间状态、结果判读和交付检查？
5. 真实角色、数据类型或运行方式的差异是否只写一句话，而实际会改变任务？
6. 截图是否缺关键状态，或整体缩小后无法读清，需要有说明价值的局部细节？

上述每一项都以当前软件确实存在为前提。优先补证据和必要操作，再补正文；不要反过来先写“应有的功能”再要求软件配合。

### 明确禁止的增页方式

- 放大字体、行距、页边距，逐段强制分页，插入空白或仅有标题的页面。
- 将同一段换说法多次出现；把每个简单按钮都扩成同一套多级小标题。
- 重复整张截图、把截图拆成没有新增观察点的小图，或一页一张图却没有操作解释。
- 大段源码、算法历史、宣传话术、无关通用环境教程、用户未需要的报告和致谢。
- 把虚构故障、不存在的权限/训练/备份/回滚等功能当成“丰富系统特色”。

检查一个增补单元是否值得保留：它是否增加了新的条件、动作、决策、结果判断或已知恢复方法？删除它是否损失某项真实使用信息？若都不是，就不应靠它扩页。

## 3. 事实规模与70页冲突时怎么办

先完成授权范围内的资料核对与真实功能盘点，形成“已有内容可支撑的篇幅—具体缺口—补取办法”的简短说明。可继续补拍、补测和补写独立部分；未知项用草稿标记保留，不编造事实，也不自行降到30/50页后宣布达标。

如果现有系统确实很小，或关键资料/可运行环境缺失而无法继续核实，给出有依据的草稿和集中缺口，请主人一次决定补资料/安排验证，或明确接受较短版本。得到缩减篇幅的明确要求才更新标准；不得把“事实优先”滥用成自动绕过70页验收的借口。扩写手册不自动授权给软件增加功能。

## 4. 最终检查的证据与结论

可复用已有项目验收记录，不要求独立长报告。每项使用“通过 / 未通过 / 未验证”，并写实际文件、页码或操作证据：

| 检查 | 通过所需证据 | 不足以证明通过的情况 |
|---|---|---|
| 事实一致 | 名称/版本、入口、能力、参数、反馈和输出能回到当前项目证据 | 只参考旧稿、默认示例或根据常识推测 |
| 完整与闭环 | 从真实能力清单核对覆盖；关键任务从准备到结果/下一步可连续执行 | 目录出现模块名；只做全文关键词检索 |
| 说明深度 | 读者能做关键选择、识别成败及处理已知问题 | 页数够，只有“点击开始—查看结果” |
| 系统特色 | 实际特征改变了业务章、案例、决策说明或证据；通过替名检查 | 全文仅系统名和菜单名不同 |
| 篇幅 | 最终PDF实测总页/正文边界/排除页/有效正文页，满足当前约定 | DOCX缓存页数、字数换算、估计“约70页” |
| 排版与目录 | 实际打开/渲染Word和PDF；按排版规范检查分节、字体、表格、目录与实页 | XML中有PAGE/TOC域但没有刷新；仅封面好看 |
| 截图 | 当前系统真实状态，图文对应，100%显示可读；导入/配置/结果能对应 | 浏览器或界面空截图；模拟结果；放大模糊图片 |
| 文件一致 | Word/PDF来自同一内容版本，正式稿无缺口、敏感路径、孤立引用 | 导出旧文件，或只检查了一种格式 |

页数和 XML/文本检查属于机械检查；真实操作覆盖属于运行验证；100%页面检查属于视觉验证。不要用其中一项替代另外两项。全书缩略图用于找异常页，再实际查看封面、目录起止、正文起止、各类核心任务/表格/截图页面及发现异常的所有页。

## 5. 完整母版与登记交存件

先保留完整手册。是否另做交存节选按用户明确的提交需求和当时官方要求处理，不默认把超过60页的母版裁成60页，更不把“前后30页”误读成“手册只能60页”或“至少70页”。

截至2026-09-09，官方公开规定见[写作方法与来源](写作方法与来源.md)：一般交存前后各连续30页，不足60页提交全部，除特定情况外文档每页不少于30行。既有含图排版与行数要求应分别核对；不能自行认定“有截图就一律豁免”，也不能擅自改变主人要求保留的版式来声称合规。若实际提交口径与固定版式有冲突，明确列出冲突并核实机构要求后再决策，不保证登记通过。
