# 手册输入与生成

生成器负责排版，不负责从空输入创造软件事实，也不会自动把内容扩成70页。先完成任务策划与证据采集，再构造输入；结构示例仅说明接口，不能把示例内容写成当前项目功能。

## 首选：chapters 自定义正文

顶层 metadata 保留现有字段：system_name、version、doc_type、date、company。名称/版本/日期须在正式生成前核实，缺失时的脚本默认值不可当作已确认事实。sources 是内部来源信息，不显示在文档中。

chapters **完整替换正文**：按输入顺序生成章节，不额外追加固定的引言、安装、模块说明或总结；封面、自动目录、正文三分节和既有格式保持不变。正文中的章节职责由内容策划保证，脚本不会自动补全漏写的业务。

每个章节节点支持：

- title：非空字符串，不手写章节序号。生成器自动编为1、1.1、1.1.1。
- blocks：有序内容块，先渲染它们。
- sections：有序子节点，随后渲染；最多三个标题层级。仅有有效子节的父节点也可，不允许只有空标题。

支持的内容块：

| type | 字段 | 排版行为 |
|---|---|---|
| paragraph | text：非空字符串 | 原有正文样式 |
| steps | items：非空字符串列表 | 编号步骤，保留正文样式 |
| bullets | items：非空字符串列表 | 项目列表 |
| table | headers：至少含一列的字符串列表；rows：等宽行列表，单元格为文本、数值、布尔值或 null | 原有三线表；行列数须匹配 |
| image | image：真实截图路径；caption：非空图名，不手写图号 | 内联居中、保持比例；自动按章连续编号 |

表格接口兼容原表格函数，机械上允许空表头字符串、rows: []（仅表头）和 null 空单元格；正式正文仍须有明确表头与有用数据，不能用空表格充篇幅或声称信息已经完整。

不提供空白页、分页凑数或任意字体覆盖块。未知块/字段、空 chapters、四级嵌套、错误表格宽度和缺失图片会报错，不能把被忽略的内容算作已经写入。

下面是**接口演示而非可提交的手册**，只展示如何安排不同业务章节：

```json
{
  "metadata": {
    "system_name": "结构演示用示例",
    "version": "V1.0",
    "doc_type": "用户操作说明手册",
    "date": "示例日期，正式稿须核实",
    "company": ""
  },
  "sources": ["README.md", "src/"],
  "chapters": [
    {
      "title": "完成本系统的核心任务",
      "blocks": [
        {"type": "paragraph", "text": "【需补充：任务目标、适用读者与完成判据】"}
      ],
      "sections": [
        {
          "title": "准备本次任务的输入",
          "blocks": [
            {"type": "steps", "items": ["【需补充：真实入口和准备动作】", "【需补充：可观察的输入检查】"]},
            {"type": "table", "headers": ["检查项", "判据", "不满足时的处理"], "rows": [["【需补充】", "【需补充】", "【需补充】"]]}
          ]
        },
        {
          "title": "执行并判断处理结果",
          "blocks": [
            {"type": "paragraph", "text": "【需补充：关键选择、动作反馈、结果解释及下一步】"}
          ]
        }
      ]
    },
    {
      "title": "结果交付与已知问题处理",
      "blocks": [
        {"type": "bullets", "items": ["【需补充：真实支持的交付方式与复核】", "【需补充：已知问题、恢复动作和复验点】"]}
      ]
    }
  ]
}
```

需要图片时，在相关节点的 blocks 中添加如下块，前提是已获得当前项目真实截图：

```json
{"type": "image", "image": "images/实际任务状态.png", "caption": "本次任务结果的核对位置"}
```

图片相对路径以输入文件所在目录为基准。图号由所属一级章累计，不因子节改变而重置。图片路径与 sources 只用于溯源，正文、图注或表格仍不应出现本机源文件名/路径。用户必须识别的公开文件名按下一节单独核对，不与截图来源混淆。

## 必要公开文件名与内部路径

默认验证会阻止正文中的本机路径/文件名。开发机绝对路径、截图源文件、临时目录和内部源码位置继续禁止；但操作手册不能因此缺失用户必须输入的启动命令或配置名称。

仅当当前交付包、界面或运行证据证明某个文件名就是公开操作接口时，可在输入顶层逐项提供 public_artifacts。每项且仅包含 value（正文会使用的精确名称）、reason（用户为何需要）、evidence（内部核对来源）。例如下列是**接口演示**，不是当前项目事实：

~~~json
{
  "public_artifacts": [
    {"value": "launch_tool.py", "reason": "用户需要执行的交付包启动入口", "evidence": "当前交付包启动说明及已验证命令"},
    {"value": "configs/task.yaml", "reason": "界面要求选择的公开配置", "evidence": "交付清单和实际配置输入框"},
    {"value": "results.csv", "reason": "用户需检查的输出文件", "evidence": "本次导出结果"}
  ]
}
~~~

- 这只是**精确名称许可**，不判断事实真伪，编写者仍须先核对。reason/evidence仅内部记录，不进入手册；sources也保持内部用途。
- value只允许明确的文件名或交付包相对路径，不允许绝对路径、UNC、file URL、上级目录穿越、通配符或重复项。必要绝对位置应改为通用的用户选定目录描述，而非暴露开发机位置。
- 允许 launch_tool.py 不会自动允许 src/launch_tool.py、其他文件或机器路径。未登记名称仍会报错，不可为了绕过检查把全套源码目录加入清单。
- 将经核实的名字/相对路径写入普通正文、步骤或表格即可，命令语法和实际执行结果仍需实测；示例配置、输出名、默认值和真实接口必须区分。
- 不存在这类公开文件名时完全省略 public_artifacts。旧输入无此键的验证行为保持不变。

## 兼容：旧模块输入

没有 chapters 键时维持原有固定八章路径，供旧稿维护或迁移使用；不是新写详细手册的默认内容架构。以下旧键和 CLI 保持可用：

- overview：purpose、audience、scope、positioning、features、scenarios。
- environment：hardware、software、dependencies、install_steps、startup_steps。
- interfaces：name、description、areas、image、caption。
- modules（或旧 features 别名）：name、description、entry、steps、outputs、notes、image、caption。
- data_outputs：name、entry、format、description；faq：question、answer；summary。

缺失内容默认生成“【需补充：…】”；overview.scope 与 summary 也不能漏检。--allow-generic-defaults 仅用于主人明确接受的内部草稿，不得用来掩盖正式稿的证据缺口。--write-sample 保留旧接口示例能力，不能把该示例当作新手册的目录决策。

如果同时提供 chapters 与旧正文键，只以 chapters 决定正文；需要的旧内容要由编写者明确迁入章节树，不能假定会自动拼接。保留来源与名称/版本字段，重新检查覆盖，避免迁移时丢失实际能力。

## 调用与导出

先按本机 Python环境说明核验文档环境，将 $python 绑定为合职责环境的绝对 python.exe，将 <skill-root> 展开为当前 skill 目录。依赖不全时核对环境与授权，不自动安装或跨环境借包。JSON 不要求额外安装 YAML 依赖。

```powershell
& $python -X utf8 "<skill-root>/scripts/generate_ruanzhu_manual.py" --input "project.json" --output "软件名称V1.0用户手册.docx" --backend docx
```

HTML 分支仅保留旧的降级内容草稿能力，缺自动目录、规定分节页码等，不能作为等价正式手册。chapters 与 --backend html 的组合会明确拒绝，不静默退回旧目录；本次不以 WeasyPrint 路径替代 Word 的正式导出。HTML 不是 PDF，不能改扩展名交付。

生成器使用 Word 原生的 toc 1 / toc 2 / toc 3 目录样式，图片段落显式清除正文首行缩进；不要改回自定义同名目录样式或让图片继承24pt首行缩进，否则 Word 更新域后的实际版式可能与脚本样式定义不一致。

生成后在 Word 中真实更新目录、页码域并重新分页，保存同一版本后导出PDF。脚本设置“打开时更新”不证明目录已经刷新；旧的 DOCX 缓存页数也不证明真实篇幅。文件锁定时不擅自关闭用户文档，覆盖既有文件前先辨归属并保留可恢复副本。

最后按[排版规范](format-spec.md)及[篇幅与质量验收](篇幅与质量验收.md)检查实际产物。生成器或回归测试成功只证明结构/机械行为，不证明当前系统事实、70页达标、截图可读或登记合规。
