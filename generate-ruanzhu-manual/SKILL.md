# 软著操作手册

固定的是格式外壳和用户任务的逻辑闭环，不是八个章名或每模块五段话。手册应使目标读者能完成真实工作、判断结果并处理已知问题；“特色”来自软件真实业务，不来自虚构功能或华丽标题。

## 按请求选择工作量

- 新写或整体扩写：先读[内容策划与深写](references/内容策划与深写.md)和[篇幅与质量验收](references/篇幅与质量验收.md)，按系统重新设计正文。正式完整版默认以**最终 PDF 正文不少于70页**为详细程度目标；这是主人的本地写作约定，不是登记法规。用户明确指定的其他篇幅优先。
- 局部修订、格式修复：只处理授权范围，不因上述默认值擅自扩写整本手册。审计请求先报告证据，不能把“审计”当成重写授权。
- 生成或改排版前读[排版规范](references/format-spec.md)；调用脚本前读[输入与生成](references/输入与生成.md)。新写/整体重写默认保留本 skill 已确认的固定格式，参数只以排版规范为准，不复刻旧样本的格式缺陷；局部修订不顺带改排版。若用户另有明确机构模板或要求逐项复刻原件，先比对并说明冲突，仅在确有实质取舍时确认。
- 需要说明取舍依据或核对登记要求时，读[写作方法与来源](references/写作方法与来源.md)。它用于方法溯源，不是每本手册都要插入的文献综述。

## 先确认事实，再设计目录

从源码、README、真实界面、运行记录及已确认资料建立简洁的“用户任务—事实证据—章节—验证”对应关系。系统名称、版本、环境和日期都要有依据，生成器默认值不算证据。旧手册只能证明旧稿曾这样描述，不能代替当前版本的实现核验。

先说清读者、业务对象、输入到产出的主流程、特有约束和哪些能力尚无证据；再决定章名、先后、拆合及取材。允许相同的大章骨架，但核心业务章节必须由本系统任务决定：数据流水线、角色办理过程、设备状态或分析决策都可成为组织主线，不限于菜单顺序。

所有适用内容要闭合：**用途与边界 → 使用准备 → 实际任务 → 结果判读与交付 → 异常恢复或安全结束**。这些是覆盖要求，不是必须逐字照抄的章名。安装、账户权限、模型训练、数据库管理、日志、总结和致谢都不能因为模板里有就硬加；不适用项在内部说明理由即可。

策划至少回答：哪些真实特征改变了目录或内容安排？读者将在哪一节做出本系统特有的选择？关键结果在哪里得到验证？如果仅换系统名和名词就能套给另一系统，应重新取材，而不只是再换标题。

## 按任务深写，不按模块平均分字数

- 对核心、多分支、高风险任务写明目标、前置状态与输入条件、入口、动作与关键反馈、参数选择依据、结果判据、已知失败分支以及后续去向。它们是信息检查维度，**不是每节必须出现的同一套小标题**；简单动作可短写并引用共用说明。
- 使用动词型任务标题；步骤先交代位置，再交代动作，必要时紧接可观察反馈。不能只写“设置参数、点击运行、查看结果”。复杂流程按实际阶段拆分，不把所有动作塞进一条长步骤。
- 新手首次成功、日常任务、参数/字段查阅、必要原理分层安排。公用环境和重复步骤只解释一次。原理只写到足以支持操作选择和结果理解，不用论文式背景、代码架构或技术名词堆叠增页。
- 在真实证据支持下选用端到端案例、参数决策表、输入合格性检查、状态流转图、结果对照或故障恢复树。无需每个系统都具备这些组件，也不固定组件数量；每个组件必须解决一个具体使用问题。
- 每项已确认、用户可见的能力都有可定位的说明；重点任务有足够证据让读者照做并判断成败。不得以“目录列出了模块”冒充内容覆盖。

## 操作证据与真实性

截图来自当前软件的实际状态。导入数据/图像、执行处理并等待相应反馈后再截图；总览交代位置，必要的局部图解释参数或结果。不同输入、配置、结果之间要能对应，不用一张空主界面代表整个流程。原截图裁切或脱敏不能改变业务结果；说明必要标注，不伪装原生界面。

区分源码确认、实际操作验证、仅旧稿记载和未确认事实。没有真实运行或截图时可以推进有依据的草稿，但不能冒称端到端验证完成；未观察到的状态不制作模拟截图。涉及真实设备控制、删除、发布等有后果的动作，截图需求不构成额外授权；只在获准的测试条件下执行。

草稿用“【需补充：具体事实】”定位缺口。正式稿不得残留占位、未证实行为、虚构默认值/指标或未经实现的功能。参数的默认值、测试观察和操作建议要分清；把建议当建议，不包装为系统保证。开发机路径、内部源码名、截图源路径和本机数据库名只作内部溯源，不进入正文、图注、表格或页眉。交付包中用户必须实际输入的启动名、配置相对路径、输出文件名不属于应隐藏的内部证据：核实它们是公开操作接口后，按[输入与生成](references/输入与生成.md)的 public_artifacts 逐项登记，再原样写清。不能以隐私为由省掉可执行入口，也不能伪造不存在的GUI替代真实命令。

## 生成与验收

新写详细手册优先使用生成器的 **chapters 自定义正文模式**，保留封面—目录—正文三分节与原有排版。legacy 模块输入仅为旧稿维护兼容；不能为了方便生成而把已经设计好的业务目录压回固定八章。HTML 分支不是等价正式输出，不能用它绕过 Word 分节、目录或页码要求。

先用代表性任务试排、校准篇幅，再生成全稿；正文70页目标不能由空白、重复截图、大行距或无关附录凑成。实际篇幅不足时按[篇幅与质量验收](references/篇幅与质量验收.md)补取有价值的事实与场景；资料不足就保留缺口，不能静默降标后称正式完成。

Word 中真实刷新目录和域、重新分页后导出 PDF，按最终文件逐项验收：

1. **内容**：任务覆盖、闭环、系统辨识度、术语/版本、参数与输出一致性；用关键路径实操证据或明确的未验证结论支撑，不拿脚本退出0代替。
2. **篇幅**：分别报告 PDF 总页数、正文起始物理页和有效正文页数；按明确的计数口径核验目标，页数达标不替代说明深度。
3. **格式**：封面无页眉页码；目录/正文独立起页与从1编号；正文使用节内总页数；核查中西文字体、缩进、行距、页边距及三线表，不仅看首页。
4. **可读性**：全书缩略图扫描与代表性页面实看；最终 Word/PDF 在100%显示下截图标签、参数和结果可读，图文对应、无截断溢出；目录页码与正文实页一致。
5. **交付边界**：正式母版与登记交存材料分开处理。未打开、未渲染、未运行或提交规则未核实的项目据实标明，不能宣称完整通过或保证登记成功。

交付核验后的 Word/PDF 路径、实际篇幅和简短结论。保留可追溯的内部证据，但不自动附加独立长报告。只有事实、内容、篇幅及格式都满足当前约定，才称正式完成。
