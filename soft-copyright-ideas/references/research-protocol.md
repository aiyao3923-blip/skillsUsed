# 领域研究协议

## 何时研究

研究只为当前模式所需的外部事实服务：

- 纯粹审阅本地工作流结构时，不必为了形式联网；
- 题目含有陌生领域、行业流程、法规、招标条件或动态登记要求时，必须核验相关事实；
- 用户已提供完整业务事实时，不要用泛泛竞品资料覆盖用户决定；
- 只有进入完整规划，才按需扩展到角色、流程、实体、规则、指标、风险、数据和交互模式。

## 最小充分研究

先列出需要验证的主张，再检索支持这些主张的来源。默认优先回答：

1. 领域边界和核心术语；
2. 参与者、职责和主流程；
3. 核心对象及生命周期；
4. 关键规则、例外和时限；
5. 指标、数据来源和风险；
6. 外部系统、硬件或算法依赖；
7. 与当前题目或交付用途直接相关的官方要求。

不要把“收集很多链接”当成研究完成。每个来源都要说明它改变了哪个问题、选择或设计产物。

## 查询构造

围绕题目词组合查询，而不是只搜索完整软件名称：

```text
<领域> 业务流程 / 参与角色 / 职责
<核心对象> 生命周期 / 状态 / 字段
<业务动作> 管理办法 / 规范 / 用户指南
<领域> 指标 / 统计口径 / 风险 / 预警 / 处置
<领域> 信息化建设 / 系统功能 / 交互模式
<招标关键词> 技术要求 / 评分 / 功能证明
```

查询结果只用于发现线索；关键结论必须回到权威原文或两个相互独立的可靠来源。

## 来源优先级

1. 法律法规、主管部门、政府平台和国家标准；
2. 行业主管机构、公共事业单位和行业协会；
3. 高校、科研机构和权威教材；
4. 产品官方帮助中心、用户指南和技术文档；
5. 公开招标文件和企业案例；
6. 新闻、博客、论坛和聚合页面，仅作线索。

竞品功能不是行业必需流程；除非有独立来源支持，否则只能标记为“产品模式参考”。

## 证据记录

推荐记录以下字段：

| 字段 | 要求 |
|---|---|
| 证据编号 | 稳定且可被决策、追踪记录引用 |
| 具体结论 | 一条记录只表达一个可核验主张 |
| 来源机构和类型 | 说明权威性 |
| 标题、URL和定位 | 便于复核 |
| 发布/更新时间 | 判断新旧 |
| 访问日期 | 动态事实必填 |
| 适用地区、行业或版本 | 防止错用 |
| 支持的设计决定 | 说明研究价值 |
| 可信度和冲突 | 记录局限，不隐藏矛盾 |

输出中应区分：

- `[外部事实]`：来源直接支持；
- `[已有文档主张]`：材料中写了，但还没有独立核验；
- `[方案建议]`：模型根据证据作出的选择；
- `[未核验]`：当前不能作为最终事实。

## 研究停止条件

满足以下条件即可停止扩张：

- 能用通俗语言解释领域边界；
- 能识别主要角色和一条主流程；
- 能列出核心对象、主要状态和决策点；
- 能说明关键数据和指标从哪里来；
- 能指出外部依赖、合规风险和不确定项；
- 新来源主要重复已有结论，或不会改变当前决策。

## 失败与降级

- 网络不可用：不要伪造引用；输出未核验项和用户可提供的替代材料；
- 来源冲突：并列呈现适用范围和差异，不擅自选取更方便的一方；
- 官方页面失效：从同一官方机构寻找最新入口，记录页面状态；
- 只能找到低可信来源：降低结论强度，不能把推测写成行业规则；
- 用户提供敏感代码、凭据或个人信息时：只读取完成任务所需部分，不上传到外部服务。
