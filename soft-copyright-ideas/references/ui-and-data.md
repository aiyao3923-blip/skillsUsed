# UI、数据与接口规划

本文件只在完成需求基线后读取。页面必须从任务、用例和状态推导，不能从固定页面模板或截图数量倒推功能。

## 页面推导链

```text
角色任务 → 用例/状态 → 所需信息与动作
→ 页面类型 → 组件 → API/数据服务 → 验收场景
```

## 页面清单

每个页面至少记录：

| 页面编号 | 名称 | 模块 | 类型 | 角色 | 核心任务 | 实体 | 状态 | 用例 | 优先级 |
|---|---|---|---|---|---|---|---|---|---|

页面编号、路由和名称保持稳定，供代码、测试和说明书引用。

## 页面规格卡

```text
页面编号/名称/模块/目的/角色/路由：
进入来源/前置条件/参数/离开去向/返回策略：
关联用例/核心实体/API/刷新时机/筛选排序/分页：
布局/核心组件/展示字段/状态标签/图表口径：
主要操作/显示与禁用条件/二次确认/字段校验/业务规则：
状态变化/成功失败反馈/通知审计：
适用的加载、空数据、无结果、错误、无权限、只读、校验失败、冲突状态：
响应式与可访问性/验收条件/代码模块/说明书章节：
```

状态应按页面类型选择，不要求静态页面虚构并发冲突：

- 列表：加载、空数据、无结果、错误、无权限；
- 表单：校验失败、成功、只读、冲突；
- 仪表盘：无数据、筛选无结果、指标异常；
- 审批/工单/任务：状态动作、退回、超时、冲突和时间线。

核心按钮必须有可见角色、可用状态、前置校验、成功结果和失败结果；装饰按钮要删除或明确为不可用的占位。

## 平台选择

根据任务发生位置、设备能力、交互密度和离线需求选择 Web、移动端、桌面端、大屏或组合。平台选择是影响架构和页面的高影响决定，未确认或未授权时只能作为候选。

## 可视化

每个图表至少定义标题、管理问题、指标公式、数据源、筛选维度、提示信息、图例、空状态、钻取目标和与明细的校验方式。没有真实空间数据时不要放地图；没有连续数据时不要声称实时趋势。

颜色不能作为唯一状态编码；同时使用文字、图标、形状或可访问的文本说明。根据目标终端说明断点、窄屏降级、键盘焦点、对比度、表单标签和图表文本替代。

## 演示数据

使用合成数据，保证实体关联、时间顺序、状态过程、列表/详情/统计一致，并覆盖适用的正常、异常、退回、超时、取消和完成情况。说明记录规模为何足以支撑页面和指标，不固定编造条数。

## 接口和 Mock 边界

核心资源提供查询、详情、创建/编辑和明确的业务动作；指标和图表使用同一数据源；统一错误结构并考虑版本/并发冲突。页面通过数据服务层访问 Mock 或真实接口，状态和规则集中定义，不能在组件内散落互相矛盾的硬编码数据。
